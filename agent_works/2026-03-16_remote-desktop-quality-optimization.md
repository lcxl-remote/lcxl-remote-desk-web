# 2026-03-16 远程桌面视频清晰度优化 (CQ/CRF 模式)

## 1. 任务背景 (Implementation Plan)
用户反馈远程桌面画面模糊，经分析发现是由于编码器（H.264/VPX）默认运行在固定码率（CBR）模式且上限较低导致的。为提升画质，计划将编码策略改为恒定质量模式：
- **H.264**: 使用 `x264` 替代 `openh264`，支持 CRF 模式和零延迟调优。
- **VPX**: 改造本地包装层，支持 `VPX_CQ` 模式。
- **前端**: 开放质量控制滑动条（0-63），支持国际化。
- **环境**: 更新 Dockerfile 以支持新编译依赖。

## 2. 任务清单 (Task List)
- [x] 更新 `signal-facade` 中的数据模型，增加 `video_quality` 字段。
- [x] 改造 `vpx-encode` 底层包装，支持 `VPX_CQ` (已改为通过 Git 依赖)。
- [x] 集成 `x264` 库并实现 `x264_encoder.rs`，支持 CRF 模式。
- [x] 恢复 `openh264` 为 `h264_encoder.rs`，实现两者并存。
- [x] 前端 `DeskConfigDialog` 增加质量调节滑动条。
- [x] 修复滑动条 0 值跳变 Bug 及国际化词条。
- [x] 更新 `Dockerfile`，添加 `nasm`、`libx264-dev` 等构建依赖。

## 3. 执行过程总结 (Walkthrough)
1. **研究分析**: 发现模糊根源在于码率控制和分辨率缩放。
2. **方案制定**: 决定引入 CRF (H.264) 和 CQ (VPX) 模式。
3. **后端改造**:
    - 修改 `vpx-encode` (Git 仓库) 支持 `SET_CQ_LEVEL`。
    - 引入 `x264` 库。用户自行将文件重命名为 `x264_encoder.rs` 以支持与 `openh264` 并存。
    - 实现了基于 `x264::Setup::preset` 的零延迟高质量编码。
4. **前端改造**:
    - 在 `vite-project` 中将 `video_encode_bps` 映射为 `video_quality`。
    - 增加了滑动条并修复了逻辑错误（使用 `??` 代替 `||` 处理 0 值）。
    - 补充了中英文国际化翻译。
5. **部署准备**: 更新了 `Dockerfile` 以包含编译和运行 `x264` 所需的系统库。

## 4. 最终状态
- 远程桌面现在支持 0-63 的质量调节。
- H.264 (x264) 和 VPX 均已运行在恒定质量模式，画面在静态和文字场景下极其锐利。
- 项目已成功适配自定义的 `x264` 和 `vpx-encode` Git 依赖版本。
