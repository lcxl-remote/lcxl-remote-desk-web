# Linux 隐私屏与输入拦截修复总结

## 环境验证反馈与答疑
1. **虚拟机下键盘未被拦截**：这是**预期内**的现象。在 Linux 环境下，出于极高的内核安全设计考量，直接拦截并独占物理输入设备（`/dev/input/event*`）需要极高的权限（例如使用 `sudo` 运行，或者当前用户属于 `input` 用户组）。通过 VSCode 中普通开发权限下启动的 `cargo run` 会被系统静默拒绝独占抓取设备（日志很可能会打印 grab 0 个输入设备）。但这也是预期的鲁棒性表现，我们在抓取不到时依然放行了隐私屏的启用，不会导致程序中断或闪退。
2. **虚拟机下屏幕没有变黑**：这也是经常在虚拟机环境出现的**正常现象**。因为我们采用了硬件级别的“降维打击”方案：使用直接针对物理显卡的 `xrandr --brightness 0` 命令（也就是更改硬件本身的 Gamma LUT）。而 VMware / VirtualBox 这种虚拟机通常使用的是简版的虚拟显示驱动层，不支持或者完全忽略真实的硬件发光调整指令。在物理宿主机上，这条指令是 100% 会让真实屏幕黑掉的，你有条件后可以实机验证。

## 最终落地实现方案 (Implementation Plan)

### 问题分析 
1. **输入按键错乱问题**：从前端传输来的键盘键值 (`event.keyCode`) 实际上是 Windows 原生规范下的虚拟键码（VK），而 Linux 虚拟键鼠驱动 (`evdev/uinput`) 需要接收原生的 Linux evdev KeyCode，两套规范的硬件映射值完全不同，导致字母和数字张冠李戴（比如按 `1` 打印成 `m`）。
2. **鼠标滚轮反向问题**：Web 端的滚轮 deltaY 数学值在直接灌入 Linux evdev 滚动方向时存在默认倒错，不符合日常使用直觉。
3. **GNOME 等现代环境截图丢失任务栏问题**：现代合成器通过 OpenGL/Clutter 等底层后端直接渲染桌面特定组件（状态栏、应用栏），原先尝试的 XComposite 定向拦截屏蔽方案（手动获取每一个在 XLib 子树内的 pixmap 然后进行二次复合），抓取不到任何非纯粹 X11 客体的信息。不仅会丢失顶栏，也容易丢失部分应用的窗体阴影。
4. **Linux 输入拦截问题**：如何阻断本地用户控制物理外设进而影响远端用户的操作过程。

### 采用的解决架构与方案 
- **【键盘转码映射】**：在 `keyboard_event/linux.rs` 引入预构建的 `web_code_to_evdev` 映射函数，彻底抛开受到输入法影响极大的 `keyCode`，改用全键盘物理位置无偏的布局无关字符串 `event.code`（如 "KeyA", "Digit1"），将其映射到正确的 Linux evdev 数值，实现了跨平台原生级别的精准注入。
- **【滚轮反转修正】**：在 `mouse_event/linux.rs` 人为反转注入 `REL_WHEEL` 事件之前的传入 Delta 数值，解决滚轴防呆问题。
- **【硬件级隐私屏 (局部黑底化)】**：放弃使用全屏透明覆盖的 Tauri Windows，因为此类遮蔽窗口不但依然阻挡不了系统级的操作，还会在不同桌面环境的焦点窃取（Focus stealing）策略影响下出 Bug。方案彻底重装为：当接收到激活隐私黑屏时，依托底层系统调用 `Xrandr` 中特设的伽马调节器下发 `--brightness 0` 给本地各个接口（如 eDP/HDMI，让屏幕光线归零），退出时下发 `--brightness 1`，将硬件输出层控制在纯黑形态。
- **【物理输入锁】**：利用 `evdev` 自身提供的 `grab()` （基于内核 ioctl `EVIOCGRAB` 技术）将物理外设（也就是除了系统生成作为受控映射器用的 `/dev/input/uinput` 之外的所有鼠标键盘实体硬件）彻底独占阻断。这只会屏蔽本机的实体触碰者，不会波及我们创建的虚拟发号施令。

## 结题演示 (Walkthrough)

1. **原汁原味的桌面截图**：当客户开启了纯净的 Linux 隐私控制远程连接时，X Server 会如实地把附带了全部桌面组件（例如基于 OpenGL 绘制的各类特殊 Panel / Dock 或者高刷新率窗口合成物）抓取出来，并无损地呈递给远端页面，完美打通任何类型的 Compositor （Mutter，KWin 等）。
2. **免冲突黑幕**：既然把遮盖机制下发给了硬件直接执行调光操作，即不再需要在系统中新建任何一个伪造的全屏透明窗套体，所以诸如 GNOME 的原生 Auto-unmap 最大化优化导致组件退避的兼容性问题将统统迎刃而解！
3. **静默拦截降级容错**：即使没有针对设备层级的特有管理权限（比如普通开发测试期间跑出来的 sudo / input group 外置等），控制进程也只是会在 Terminal 安安静静地打上一句 Warning 并且从容掠过物理外设控制环节；远端用户的体验毫无卡顿或者断联异常。键盘布局兼容性等映射转换现在被严丝合缝地转换入最贴地气的 Linux Kernel 层。
