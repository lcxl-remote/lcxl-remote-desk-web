# Contributing Guide

Thank you for your interest in LCXL Remote Desk Web! We welcome all forms of contributions, including bug fixes, documentation improvements, new feature suggestions, or code submissions.

## How to Participate

### 1. Reporting Bugs

- Before submitting an issue, please search if a similar issue already exists.
- Use the provided Bug Report template.
- Please describe the issue in as much detail as possible, including reproduction steps, detailed logs, and environment information.

### 2. Suggesting Features

- Use the Feature Request template to describe your idea.
- Explain the use cases and the value of the proposed feature.

### 3. Submitting Code (Pull Requests)

- **Branching Policy**: Please create functional branches based on the `main` branch (e.g., `feature/your-feature-name` or `fix/your-bug-fix`).
- **Coding Standards**:
  - Backend Rust code must be formatted with `cargo fmt` and should be free of `cargo clippy` warnings.
  - Frontend code must follow ESLint standards.
- **Commit Messages**: Please use clear English descriptions for your commits. We recommend following the [Conventional Commits](https://www.conventionalcommits.org/) specification.
- **Testing**: If possible, please add unit or integration tests for your changes.

## Development Workflow

For detailed environment setup and workflows, please refer to the [Development Guide](DEVELOPMENT.md).

## Contact Information

If you have any questions or would like to discuss further, please feel free to open an issue to contact the maintainers.
