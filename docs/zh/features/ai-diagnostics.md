# AI 诊断

桌面上下文既可通过“添加上下文”手动选择，也可由 AI 按当前需求申请“桌面会话”“语义 UI 观察”或“当前屏幕截图”。未选择上下文的新会话也能提出申请；用户在权限卡中批准后，助手自动继续原问题，拒绝则不会读取。授权受目标设备、当前输入、有效期限和调用次数约束，失效后需要重新申请。屏幕截图只对支持图片输入的模型开放，读取授权不包含鼠标键盘控制权限；设备离线、系统权限不足或能力被本地设置关闭时，确认也不能绕过限制。

在已有会话中，点击“设置会话定时续跑”进入定时任务页面，再填写任务说明和单次执行时间。确认提交后直接创建并启用，不需要保存草稿或再次启用。设备和会话沿用原会话，时间按页面所选时区输入、转换为 UTC 保存。如果原会话的需求版本已改变，创建或启用会被拒绝，请返回会话重新设置。可在“会话续跑”页签管理任务，并从运行历史查看结果。已完成任务可改名、删除和查看历史，不再提供改期；若要再次续跑，请从原会话创建新的定时任务。

已启用的定时续跑不会被后续普通聊天取消。到期后等待会话空闲，在最新上下文中执行批准的任务内容，并受原启动时间窗口限制。只有显式暂停或取消才停止调度；开始执行后新输入仍会阻止旧轮次继续操作。

“任务契约”入口显示已保存的契约版本、运行限额、发送账号和收件人，以及自动权限的资源与操作范围。没有保存契约时，可以点击“从成功录制生成待审核契约”。服务端依据最新成功录制的已验证读取和操作回执生成权限范围，绑定回执中的账号标识和收件人，并核对正文的数据来源；生成只保存待审核契约，不会授予权限或启用任务。证据不完整或同一工具包含不同操作而无法自动归纳时会拒绝生成。附件必须有同次录制中已验证的文件创建回执。已有契约不会被此操作覆盖。准备草稿与发送消息分别记录权限：已验证的草稿可以形成可变正文约束，但不能作为已发送证据。Gmail 扩展的页面引用和草稿快照现绑定可见登录账号，发送校验和契约目的地使用该账号；缺少可验证账号时不能准备扩展草稿或发送。Slack 要求扩展页面提供可核对的工作区和成员身份，只有浏览器配置标识不够；身份缺失或不唯一时不能准备草稿或发送。实际 Slack 页面兼容性仍需验收。跨次运行的实际发送仍待完整验收。查看本身不会批准权限。已保存的契约与当前任务版本一致时，可以点击“核对录制并准备发布”；找到对应的成功录制后，勾选确认权限范围、固定目的地和预算，再点击“确认权限并发布”。服务端会重新验证当前权限和真实录制证据，成功后启用调度。授权默认不自动到期，可以通过“撤销任务授权”单独撤销。发布不等于执行成功；独立任务的完整后台执行和真实发送仍在开发验收中。

在被控设备本机登录 owner 后，打开“本地 AI 策略”中的“本机网页消息权限”，先读取当前策略，再分别设置 Computer Use 总开关、浏览器扩展、草稿准备和消息发送开关并保存。开启发送不自动开启其他开关，也不批准任何消息或自动任务。保存需要设备 worker 确认同一版本，能力列表随后按设备心跳刷新；冲突或未能确认生效时须重新读取，页面不会自动重试。Manager 和远程页面不能修改这些本地开关。关闭开关会阻止后续未派发操作，不会撤回已经发送的消息。

Gmail 的扩展发送适配器会对比页面快照时与点击发送前的可见 Google 账号。账号无法唯一识别、缺失或已变化时，返回“确认未发送”且不点击；点击后账号变化则保持“结果未知”，不会用另一账号的提示证明送达。账号标识也随页面引用进入草稿快照和待审核契约；独立任务仍须在新运行中核对同一账号，完整后台执行和真实发送尚待验收。

工具执行结果、用户消息和 AI 回答是会话历史，不会因为时间经过或授权到期而从模型上下文中清除。只有达到上下文容量阈值时才进行窗口裁剪或摘要压缩；原始聊天记录仍保留。历史结果记录当时发生的事实，不代表设备当前状态，也不授予再次执行权限。新操作仍校验授权期限、目标身份和必要的最新状态。模型目的地或来源授权变化仍会限制对应内容的发送。

## AI 助手会话界面

恢复聊天记录、生成会话标题和统计消息数量时，不展示服务端用于续跑的内部控制消息。这些消息仍保留在持久化执行上下文中，不算新的用户输入，也不增加操作权限。

macOS 原生文本文件操作不要求开启语义观察或把应用保持在前台；仍受 Computer Use 总开关、会话目录和逐操作授权限制。

文件操作保留设备的 Computer Use 总开关，不再单独配置文件创建开关或设备级目录白名单。在 AI 助手当前会话的“目录”面板中填写被控设备上的目录并点击添加，也可以让 AI 申请目录后由你确认。目录必须存在，使用规范绝对路径；如果解析后的路径与输入不同，需要核对后再次确认。目录仅属于当前会话，刷新后仍可查看和移除，不会自动带入新会话。目录引用有效期为 24 小时，使用时仍校验目录身份；到期后请移除并重新添加。添加目录不代表批准其中所有文件操作：读取外发、创建、修改和删除仍各自受实际操作授权约束。目录申请获批后可发送“继续”，由 AI 申请所需的具体操作。创建不覆盖现有文件，支持空 UTF-8 文本，写入上限为 64 KiB。

Web、iOS 和 Android 的修改／删除确认卡展示设备回执中的文件名、完整 SHA-256 与来源调用 ID。修改同时展示原文匹配片段和替换内容，或完整替换文本；删除明确提示可恢复删除。每次只批准一次精确操作，缺少可核验的确认摘要时不能批准，不以 AI 自述的申请理由代替具体内容。

macOS 文本工具包括 `update_text_file` 与 `delete_text_file`，能力列表保留原始 key 并提供本地化介绍。修改可完整替换或替换唯一匹配片段，必须绑定当前会话中完整读取或已验证创建／修改回执的文件版本及 SHA-256；每次修改／删除均须精确确认，一次授权只执行一次。目录元数据只列举直接子项，选择其文件引用后仍需另行批准内容读取和模型外发。截断读不能用来覆盖整份文件，符号链接、硬链接、越界或版本冲突会被拒绝。

修改和删除在原目录下保留私有恢复目录：`approved-before.txt` 是批准前独立副本；删除还把原文件移到该目录的 `original`。删除没有永久删除降级。Web 文件回执默认折叠，展开可看文件名、字节数、摘要与恢复位置；异常格式保留原文。若提交后发现并发冲突，会显示“结果未知”，保留恢复信息，不自动回滚或重试。请先核对目标和恢复材料，不要直接覆盖同时产生的新文件；未知结果的恢复回执在重新打开会话后仍可查看。

Web 中的“命令执行结果（来自设备）”默认折叠，点击标题可展开。标准回执按退出码、执行耗时、标准输出／标准错误展示，终端模式保留合并输出；无输出、截断及脱敏记录会明确标注。可另行展开原始回执；非 JSON 或无法识别的格式直接原样展示，不影响已保存的原始结果或 AI 解读。

继续旧会话时，历史不会按时间过期。模型或来源授权变化时仍检查内容是否允许发送给当前模型。新产生的回合错误随会话保存，刷新或重新打开页面显示同一个具体原因；新回合开始后清除旧错误。升级前未保存的具体错误无法追溯恢复。

系统设置 → 上下文管理（`/system/context-management`）可切换摘要压缩与窗口裁剪，默认开启摘要压缩。设置在下一轮生效并在重启后保留。压缩会额外调用当前模型，可能产生费用；失败会明确报错，不静默改为裁剪。

后台命令结果的单独解读不会重置正常会话的圆环基线；新增结果和回复仍计入占用。真正发生摘要压缩或历史窗口裁剪时，对话区会分别显示简短系统提示，恢复会话后仍可查看。提示不代表删除原始聊天记录。旧版本已经被临时解读覆盖的统计会在下一次正常编排后刷新。

AI 的自然语言回答沿用界面发送消息时的语言；审批恢复和后台续聊使用会话中保存的语言偏好。语言偏好不改变工具、命令、JSON 字段或权限。尚未保存语言的已有会话需正常发送一次消息后记录偏好。

续聊时，AI 可按需读取历史；历史内容不会因时间经过而不可用，但仍须获准发送给当前模型。历史命令不会自动重跑。

发送按钮所在行的左侧圆环显示上下文预算占用百分比。悬停或用键盘聚焦可查看压缩／裁剪阈值、已用字节、剩余预算和当前文本草稿的预计增量。阈值采用最近一次编排扣除系统提示与工具定义等开销后的历史预算；摘要、保留消息和之后新增的回复、工具结果也会计入占用。工具或上下文选择变化可能改变下一轮预算，草稿预计值不包含尚未读取的附加内容，因此剩余字节不是可输入的精确字符数。压缩／裁剪后按实际保留窗口重新计算。尚未取得预算时显示“—”，不是 0%；旧会话需要一次新的模型编排后才会产生数据。

权限申请仅在待确认或需重新评估时显示在主区域；已结束申请默认隐藏，点击「权限申请记录」图标可在可滚动面板中查看状态和详情。审批结果不代表工具执行成功。

输入区底部与「发送」按钮同一行，左侧依次为上下文圆环、「任务详情」图标和「权限申请记录」图标。悬停可查看名称，点击分别打开详情侧栏与权限历史；右上角不再放置任务详情文字按钮。

裁剪／压缩提示固定在实际发生的消息边界，并显示服务端记录的时间；后续消息不会移动提示。无法定位的旧记录放在折叠的历史调整区，缺失时间显示未记录，不使用刷新时间替代。

后台命令结果解读没有工具权限；若模型输出伪工具调用，系统会在展示前拦截并最多纠正一次，仍失败则明确报错。原始命令结果保留，正文里的新命令不会执行。

对话区上方提供「历史会话」与「新建会话」；不再单独显示连接状态行。「AI助手对话」前的图标以绿色表示信令已连接、琥珀色表示正在连接、灰色表示助手已关闭；悬停可查看状态说明，屏幕阅读器也可读取。悬停对话标题可查看已选目标名称。历史列表显示当前设备最近 100 个会话，选择后恢复记录并可继续对话；当前任务或请求处理中可查看列表，结束后再切换。空会话只保留输入框提示，不另显示重复说明。

除了手动控制，LCXL Remote Desk 还让 AI 模型**读取并分析**设备状态，并在经过认证的设备所有者明确批准命令后对诊断采取行动。

::: info 通过访问码连接时
通过[访问码](/zh/guide/access-codes)连接时，会话会受到权限限制。只有设备所有者直接登录自己的设备时，才能逐条确认自由命令；其他用户和共享访问会话仍然只能使用命令模板，或保持禁止执行。
:::

## 工作原理

AI 由**中心信令服务器**（“中心大脑”）编排。设备是**瘦被控端**，按需提供只读证据；所有者确认后的命令通过另一条密封执行路径返回设备。当用户在会话中提问（如*“这个系统为什么这么慢？”*），中心服务器驱动一条严格流水线：

![AI 诊断与所有者确认执行流程](/architecture/ai-diagnostics-cn.svg)

1. 中心大脑向被控端请求**只读证据**（系统信息、进程、端口、日志、截图）。
2. 被控端在本地**采集并脱敏**证据；脱敏失败会立即中止，原始截图数据也会在离开设备前移除。
3. 中心大脑**调用模型**（仅在被控端脱敏成功后）。
4. 中心大脑运行多轮工具循环，并把回答流式回传浏览器。
5. 如果模型请求执行命令，诊断流程会暂停等待确认；浏览器会完整展示命令解释器、命令内容、工作目录、超时时间和服务端判定的风险等级，用户明确批准后才会下发。

诊断面板提供明确的尺寸调整区域：拖动左边缘可调整宽度，拖动底边可调整高度，拖动左下角可同时调整宽高；拖动标题栏可在远程桌面视图范围内移动整个面板。视图位于底部时，流式回答会自动跟随最新文字；用户向上滚动查看历史内容后，自动跟随会暂停，并显示一个向下箭头按钮，可随时快速返回最新内容。

## AI助手的逐命令授权

AI助手使用逐项权限卡承接 owner 命令确认，不再额外弹出旧诊断审批框。在确认执行模式中，owner 可申请不在黑名单中的模板外命令，包括 `du`、`df -h`、管道和多行脚本；只读/仅建议模式、非 owner 或共享访问并不因此获得执行权限。

确认卡展示完整原始命令、shell、工作目录、目标设备/桌面会话、有效时限和 stdout/stderr 上限。空工作目录表示被控执行进程的默认目录，不保证为主目录。模板外命令按 Critical、可能产生修改处理：黑名单不是 shell 沙箱，shell 会解释获批脚本，系统不会自动提权。一次授权只执行同一份冻结计划一次；输入、计划、目标会话或当前策略变化后须重新确认。结果未知时保留原任务且不自动重发。缺少完整有效确认信息的请求不能批准。

普通非交互命令不要求 PTY 或应用处于前台；目标离线、系统权限拒绝、超时和取消仍按实际结果报告。

后台命令结束后，Web AI助手会单独展示设备保存的原始命令结果，包括超时失败；这不是 AI 生成的回答。新批准的精确命令在派发时固定结果解读期限：该次批准的最长执行时间，再加 5 分钟投递与解读余量，并受会话授权范围的期限限制。因此，运行超过 5 分钟但仍在允许时限内的命令，不需要再次批准才能解读结果。这不改变等待审批的期限，也不延长命令本身的执行时间。

自动解读仅向原模型发送对应用户需求与本次结果，不重发旧截图或整段历史，也不启动新命令。撤销授权、模型或上下文变化、新需求取代旧需求、结果校验失败或解读期限真正到期时，自动解读仍会停止，原结果保留。升级不为已完成的旧任务补发授权，不自动重跑命令。

被控端「系统设置 → AI 策略 → 单条命令执行时间上限」可配置为 10–7200 秒，默认 600 秒。实际执行还受该次确认卡上的申请时长限制；进入后台不重置计时，调大设备上限也不会延长已经批准的命令。

## 关键特性

- **瘦被控端**——设备从不运行模型推理、也不持有供应商凭据；只在中心大脑请求时采集并脱敏证据。
- **只读数据采集**——系统信息、进程、端口、日志与可选截图，由被控端采集策略本地把关。只有声明支持图片输入的模型才会收到截图；原图只在当前活动轮需要时短暂保留，回合结束后改为有限的文字元数据，不进入会话历史。
- **模型无关**——兼容 OpenAI 兼容端点与 Anthropic 端点，在中心统一配置。
- **默认只给建议**——模型可以提出修复建议；真正执行必须由用户明确确认，并受每台设备的本地执行上限约束。
- **所有者确认后执行**——在「逐项确认」/「会话已批准」模式下，经认证的所有者可批准非模板 PowerShell、pwsh、bash 或 sh 命令。此类命令一律显示为**严重风险**，界面只声明检查了有效黑名单。
- **按目标设备检测命令解释器**——Desk 服务建立连接时，会以有界且无副作用的方式检测可用的命令解释器。模型只能从检测结果与执行器白名单的交集中选择，并优先使用推荐项。如果模型请求了其他解释器，服务端会返回当前可用列表，模型可以改用其中一个选项重试。
- **不能自行批准**——模型可以请求命令，但不能批准自己的请求。批量运维、自动化、MCP、共享访问和非所有者操作仍然只能使用模板，或保持禁止执行。
- **回合有界且可继续**——中心循环在同一类工具调用过多时停止；已经生成的输出和工具结果仍会展示并持久化，用户可在同一会话中发送“继续”等后续问题。
- **后台命令可持续跟踪**——批准后的命令运行超过 **8 秒**时会转为后台任务，不再占用当前诊断回合。诊断面板会显示任务编号，方便用户、模型和后续完成事件相互对应。命令会持续运行，直到正常完成、用户取消，或达到设备设置的单条命令执行时间上限。

  便携模式和开源信令服务会把任务及其完成结果保存在 SQLite 中。信令服务重启后仍能补发尚未送达的结果；实时结果丢失时，也可从被控端的执行记录恢复。任务完成后，系统会自动发起一次有界的只读跟进，让模型解释结果，但不会在无人确认的情况下执行新命令。管理员开启自动化后，Manager 也提供相同能力。
- **易读回答**——助手正文按 GitHub 风格 Markdown 渲染，支持标题、列表、代码和表格；原始 HTML 会被忽略，也不会加载模型提供的图片 URL。
- **对话可以恢复**——Manager、便携模式和开源信令服务都会保存会话快照。即使前端漏掉最终状态的实时通知，也能恢复已经结束的回答和工具结果，不会一直停留在“等待确认”。
- **工具调用可检查**——点击工具时间线中的任意一项，可以展开查看模型生成的 JSON 输入，以及返回给模型的脱敏、限长输出；已结束的回合和恢复后的历史会话同样保留这些详情。
- **共享内核**——传输中立的诊断逻辑集中在 `desk-diagnose-core` crate，由中心大脑复用，杜绝行为漂移。

owner 选择的文件、目录和终端附件只保存有界展示元数据、不透明设备引用及来源标签，不保存正文；选择附件不授予执行权限。开源 Signal 在 SQLite 中原子保存每次新元数据操作及其首次回执。同一请求重试返回首次 `changed` 值，重连或模型配置移除后也一样，不再次改变附件、更换模型目的地、延长期限或重新激活已撤销选择；同一请求 ID 携带不同操作内容则拒绝。撤销已有附件不要求配置模型。活动回合期间拒绝新的附件变更，原回执在当前 owner 和目标检查通过后仍可重放。回执不代表附件当前状态，应刷新权威会话快照。真正读取时仍由原设备校验引用；元数据回执不等于完整对象读取或移动控制验收通过。

若保留的选择元数据没有原回执，Signal 不从当前状态反推首次结果，而是拒绝该请求 ID；刷新快照后可使用新请求 ID 提交新的显式操作。升级不会重写既有附件或权限。

实时能力选择在 Signal 与 Manager 上共用 `UpdateDeviceAssistantContext`（638）→ `DeviceAssistantContextUpdated`（639）。选择只保存绑定当前 worker 代次、模型目的地和 readiness 期限的有界元数据，不授予工具权限，也不包含截图或文档正文；`CurrentScreen` 仍是显式单回合输入，不能通过 638 持久保存。完整相同请求返回首次 `changed`（包括 false），不刷新元数据；同 ID 更换选择时拒绝。清空实时选择不要求模型可用，也不删除文件或终端附件。即使租约过期，活动回合仍拒绝新选择更新，须先由原恢复流程收尾。成功与失败都保留传输和客户端请求关联。当前状态应读取会话快照，不能把历史回执视为当前仍在选择；该元数据链路不等于完整实时读取或移动端验收通过。

对于新的AI助手输入，Signal 将精确读取工具与对象选择随消息原子保存。同一消息 ID 更换正文、来源标签、主体或选择时拒绝；权限续跑恢复原选择和截止时间，不因后来新增附件或工具恢复 ready 而扩大读取范围。没有原对象选择记录的旧输入不会自动补造选择。对象读取发送前、收到结果后都会复核当前输入和附件状态；文件、表格、终端及 iWork batch 使用原引用、请求与附件中更小的上限，以及原模型目的地和来源标签，不用展示名称判断文件类型。过期、撤销或已被追问替代的选择正常拒绝，超限或携带图片的对象结果不会重新贴标签后交给模型。这些检查不替代 capability grant 和设备端引用校验，也不代表完整移动端或权限续跑验收已通过。

当可信运行时明确提供输入来源标签时，共享助手循环保留这些来源，不再追加会话中其它无关的 active 附件；模型输出和 owner 消息的传递来源仍会记录。来源记录本身不授予新的读取或外发权限。

下述“原输入选择”限制针对用户附加对象的读取路径。会话已批准目录和可信文件结果引用是另两种显式选择路径，读取前仍须验证当前目录授权、精确输入和来源证据，并单独申请操作权限；不是读取设备上的任意文件。

工具执行结果、用户消息和 AI 回答是会话历史，不会因为时间经过或授权到期而从模型上下文中清除。只有达到上下文容量阈值时才进行窗口裁剪或摘要压缩；原始聊天记录仍保留。历史结果记录当时发生的事实，不代表设备当前状态，也不授予再次执行权限。新操作仍校验授权期限、目标身份和必要的最新状态。模型目的地或来源授权变化仍会限制对应内容的发送。

Signal 权限决定重试在当前调用者和在线目标校验通过后返回首次决定，即使当前 readiness 不可用、授权已过期/撤销或原输入已被新问题替代也一样。完整决定的各项内容和限制必须与首次一致，条目顺序可以不同。重试不新签授权、不恢复次数、不改会话，也不另起模型续跑；原请求或决定记录缺失/损坏时，不能从当前批准状态反推回执。响应 `state` 是历史决定回执，不是当前权限或已续跑的证明。

新决定还会在同一 SQLite 事务保存续跑领取记录。Signal 周期扫描尚未领取的续跑，不要求手机或原 HTTP 请求持续在线；等待唯一可确定的认证目标及新鲜 readiness，再检查原输入、模型目的地和当前授权。会话领取与 `started` 状态一起提交，重复唤醒不能再次启动同一续跑。新问题会替代尚未领取的旧续跑；已经 started 的续跑在崩溃后不自动重跑，而是核对原租约与动作账本。这些恢复检查不延长引用、授权或来源留存，也不代表全部 Provider 和手机运行时流程已验收。

AI助手接受运行中追问时，共享循环会在首次和最终保存边界重新检查输入版本，避免把旧回答当成新需求的结果。普通存储失败仍按错误处理，不伪装成追问替代；撤回旧回答也不表示已开始的设备动作取消成功。

共享执行接口区分运行时确认的“未执行”和用户拒绝：若执行后端确认动作在派发前结束，循环记录未执行原因并停止本回合后续写操作，不将其显示为用户取消。这个内部结果本身不授予执行权限，也不代表所有执行后端已经具备相同的持久化恢复能力。

执行后端也可提供已经验证的原始结果标签。共享循环验证结果字节与标签匹配后原样保留，不在投递时重新生成来源或延长有效期；不匹配时拒绝使用结果且不确认投递已消费。该标签不隐含模型外发授权。开源 Signal 为已绑定的副作用 Computer Action 保存原始完成回执，包括前台等待者退出后收到的迟到结果；前台执行、主动等待和完成发布使用同一套经过校验的结果投影。旧命令结果与内联浏览器读取保留既有标签路径。

Computer Action 取得明确执行器接纳、且已有冻结的后台执行策略时，可以在前台预算结束后继续作为同一个原任务运行。owner 快照一致读取对话、授权和任务状态；任务变化推进展示序号，不使运行回合的租约失效。完成结果保存后才确认消费，超期先变为未知，等待真实结果对账。有界、无工具的模型解释必须沿用仍有效的原模型目标和上下文外发选择；Secret、新输入、上下文/模型变化、标签过期或 replay 不可用均不能被静默重新授权。自动解释被拒绝时，owner 仍可看到原始结果。这些 OSS 原任务现已接通持久 owner 取消：只向原连接重试停止，不重复动作，也不迁移到重连连接。停止确认不是终态，只有原生暂停回执才显示已取消，迟到成功或失败仍以原结果为准。这不代表全部 Provider 或完整移动控制已通过验收。

带回执的终态不等于成功：后端确认失败时，共享循环仍按原标签保存结果，并在保存成功后确认投递，但工具状态显示失败、同组后续动作停止。主动等待得到原动作的失败回执时也遵循这一规则，不用新的等待调用替换原调用身份。若当前工具组尚未结束，先保留未消费回执，后续独立等待再取原结果；结果未知仍是未知，不因收到消息就被改成失败或成功。

事务型执行后端可返回绑定原输入、租约、调用和保存后会话版本的回执。共享循环只接受本执行者自己的连续版本推进；即使事务之后报错，也保留该推进以便正确保存错误。它不会读取最新版本来绕过撤销或新输入造成的并发冲突，也不是工具执行授权。开源 Signal 默认仍走原执行入口，不需要为此引入 Manager 的共享存储。

个人AI助手与 Manager 共用独立的编译期策略版本，不受无关组织策略计数器影响。旧版本审批不能自动升级并续跑；发送新的明确请求后，新回合才采用当前策略，历史消息和旧授权不会被重签或补回次数。自动续跑和授权签发都必须匹配当前版本，版本一致也不替代目标设备 readiness 与授权撤销检查。普通终端 Copilot 的策略语义不变。

浏览器 Provider 使用两端共享的闭集输入预检：输入大小受限，选中 BrowserSurface 必须未过期，动作范围与风险由服务端派生。通用填表和元素激活仍按 InputFallback 处理，Gmail/Slack 草稿交接不会变成发送操作。预检通过不是执行授权，后续仍需原有 grant、外发检查、持久化派发与目标设备校验。

桌面语义操作的执行入口、权限申请和 grant 签发共用严格输入解码：只接受 UiElement 与 Invoke/Select/Focus/Toggle、有界 SetValue，Scroll 仍不可用。应用授权可包含 Toggle 动作，但这不表示每个原生控件都支持它；原目标设备继续校验引用到期、会话身份和实际支持动作。中央校验不能替代 Accessibility/UIA 的原生执行与读回，也不绕过本地权限、writer lease 或输入抢占。

中心下发的 Computer Action 不要求浏览器保持远程桌面连接：在已有单 worker 的便携/DeskServer 路径中，可以直接交给该 worker；启用多会话路由时仍必须有明确的会话绑定，不能猜选桌面。动作处理器在交付 worker 前拒绝请求时，使用原请求关联的 `ComputerActionCompleted` 报告“确定未开始”，而非等待超时；这不撤销其他动作，也不放宽授权、readiness 或本地能力限制。

受信中心可用 `CancelComputerAction` 请求停止原 Computer Action。daemon 校验授权后将批准者与完整 action/work/generation 传给原 worker；无明确会话时不猜选桌面。`ComputerActionStateReported` 的 `CancelRequested` 只确认已使匹配 writer 失效，不表示系统调用已撤销或动作未发生。后续 adapter 步骤被阻止，但仍以原完成回执或未知结果为准；writer 被取消、抢占或到期后，必须等待原操作释放才允许下一写入者。daemon 与 worker 必须使用同一构建，取消 IPC 的批准者字段不能与旧布局混用。

### Linux 能力边界

在 Linux 上，助手按能力逐项声明可用性。系统信息、进程与网络检查、容器检查、终端输出读取，以及所有者确认后的 `bash`/`sh` 执行，都沿用与 Windows、macOS 相同的瘦被控端和确认边界。在已经启动 systemd 的主机上，还可查询 `systemd` 服务状态和有界的 `journald` JSON 日志；如果缺少 systemd 运行时、`systemctl` 或 `journalctl`，对应两项能力会明确显示为不可用。日志可见范围仍受 Desk Server 进程自身权限限制。

Linux 文件能力只处理用户明确选择的文件和目录，模型不会看到原生路径。目录枚举与读取基于句柄相对操作，拒绝符号链接，在有界读取前后重新验证对象身份，也不会隐式递归。创建产物必须经过确认，并且只能写入设备精确配置的允许目录；实现先写入权限为 `0600` 的私有暂存文件，再用 Linux 的 no-replace 原子重命名发布，绝不会覆盖已经存在的目标。

Linux 桌面 UI 检查/操作、屏幕 Computer Use 和浏览器 Computer Use 目前仍不会声明为可用。代码已经能识别 Linux Chrome 安装与用户配置目录，供后续浏览器适配器使用，但这不会绕过 Linux 交互会话、前台窗口、受保护输入框和本地输入所有权等尚未完成的安全证明。Wayland 远程桌面采集属于另一条传输能力，本身不能满足这些 Computer Use 门槛。

::: tip 仅被控端模式需要远端中心服务
无界面的 `desk-server` 是纯被控端，不内嵌信令服务器，因此必须连接远端信令服务或 Manager 才能使用 AI 功能。便携 `default` 模式在同一进程内包含信令服务，可以独立使用。
:::

AI助手的 live Office、Numbers、Pages 和 Keynote 读取现将所选设备签发的文档引用随原输入保存，权限续跑不会重新选择较新的前台文档。派发前与收到结果后都会检查原输入、模型目的地、当前 worker/引用及原期限；目标变化或过期时拒绝，不向模型投递其正文。Office 授权与 live iWork 一样使用精确对象资源合同。结果来源标识原目标但不外露可执行 token，留存不能超过原期限；iWork batch 仍走文件附件。live 输入在接收和读取前还必须匹配当前 active 的持久 638 选择；权限等待期间撤回后不得续跑且不消耗 grant，后来重新选择也不能复活旧输入。Android/iOS 严格关联 639，断线后只重试同一个 client request 身份。这些检查仍不等于完整移动运行时或真实应用验收。

开源 Signal 还会在每次非浏览器读取前后复核原输入、当前 grant 与 readiness。授权限额会收窄发往主机的 typed 参数，并约束完整返回 payload（包括错误正文和图片元数据）；超限内容只产生固定错误，不会获得可供模型使用的结果标签。标签绑定已经验证的精确结果字节，期限不晚于原 grant 或所选数据。读取过程中输入或授权发生变化时，已经收到的 Provider 终态仍会准确持久化，但正文不会释放；明确收到的结果不会被误记成允许自动重试的 `OutcomeUnknown`。

## 配置

**模型提供方**（供应商、base URL、模型、API Key、输出格式、授予的执行模式、单回合推理轮次上限、单回合同一工具调用上限以及命令审批超时）在**中心信令服务器**上配置。推理轮次上限默认 **40**、取值范围 **1–80**，统计的是模型响应轮次而不是单个工具调用，并且不得小于同一工具调用上限。同一工具调用上限默认 **20**、取值范围 **1–50**；即使参数不同，只要工具类型相同也计入。两者都与 Desk 服务端的同时运行命令进程数相互独立。**API Key 是严格的服务端密钥**——绝不回传浏览器、绝不写日志、绝不进任何公开设置 DTO。

**命令审批超时**控制 AI 新建议的命令可以等待设备所有者确认多久，默认 **120 秒**，取值范围 **30–1800 秒**。信令服务会在创建审批时冻结该值，因此修改设置只影响之后的新建议。确认卡会把审批窗口与设备强制执行的**命令运行上限**分别展示；后者仅在批准命令后开始计时。此设置不会修改被控端 ConfirmExec pending 的有效期，也不会修改设备另一条远程访问审批（Gate B）的超时。

保存按钮旁的**「测试连接」**按钮会对表单中当前显示的提供方配置做端到端探测，包括尚未保存的修改，并且测试本身不会保存配置。文本模型会收到极小的单词回复探针；开启“支持图片输入”后，同一个按钮会发送仓库内置的视觉探针，只有模型读出其中的标记才算成功，结果会列出已验证的 `text` / `image_input` 能力。API Key 输入框留空时复用已保存的密钥；新输入的密钥只用于本次测试，直到点击保存才会持久化。API Key 全程留在服务端。

接口协议采用精确值并 fail-closed：只能选择 `open_ai_chat_completions` 或 `anthropic_messages`；空值、未知值和预留值会显示为“不支持”，不能保存或测试。Standard、DeepSeek、Anthropic adaptive/manual 与 Custom preset 只会填充明确请求选项，运行时绝不根据模型名或服务商名称猜测行为。

OSS 的预设会把 Standard 物化为 `{}` 与 512/4096 的探针/运行预算；DeepSeek 显式关闭 thinking，预算为 512/4096；Anthropic adaptive 使用 `display: omitted` 与 4096/8192。由于该 singleton 还承担存在 512 token 硬上限的终端补全，manual 预设被禁用；仅当目标服务接受小于 512 的手动预算时，才通过 Custom 配置。任何预设都不会填写 `max_context_bytes`。

表单还要求填写 4 KiB–16 MiB 的**历史上下文字节预算**（`max_context_bytes`）。它衡量从本地历史发送的序列化对话，包含工具调用/结果以及必需的 replay 状态，但不计另行注入的 system prompt、工具定义、服务端元数据与图片 data URL 字节。它不是服务商的 Token 上下文窗口。程序和小型连接探针都无法取得任意兼容端点的真实上限，请根据上游模型文档和实际请求组成保守填写。探针 observation 绑定配置 revision；配置变化后会明确显示为陈旧。

推理/thinking 是私有协议状态，不是回答正文，UI 不展示。当工具续调要求精确状态时，信令服务可能保存不透明 replay envelope，例如 DeepSeek `reasoning_content`，或保持原序的 Anthropic thinking/redacted-thinking、签名与 tool block。它不会进入 transcript 响应、安全审核输入或日志，但仍可能增加服务商 Token 用量。

长对话会完整持久化并继续显示。历史越过所配高水位后，只向模型发送按完整消息/工具组截取的尾部窗口，并在该回合显示行内提示，明确说明较早历史本次未发送；可见记录没有被删除。若最新不可拆分消息或工具组本身超过预算，请求返回 `AI_CONTEXT_ITEM_TOO_LARGE`；请提高配置预算，或缩短本次输入后重试。

每台设备另在自己的设置里保留两项**本地**控制：**执行上限**（AI 在该设备上可用的最高模式，用于收紧中心授权）与**证据采集策略**（`allow_logs` / `allow_screen`，设备对“哪些证据可以离开本机”的最终决定权）。

Linux 被控端的同一本地 AI 策略页面还可控制供需要标准输入的已批准命令使用的**一次性 PTY 执行**。该设置是整机级别并默认开启；关闭后会阻止新的 PTY 派发，但不会终止已经运行的命令。**交互式提权**是独立、默认关闭的从属开关，在 ServiceDaemon 的 root containment 路径可用前会保持禁用。PTY 输入按普通字节流中继：是否回显由远端程序的终端模式决定，LCXL 不识别、不留存这些输入，也不另设密码字段。

## 安全

设备读取失败且错误标记为不适合交给模型时，在后续模型调用和会话保存前替换为通用工具失败说明，不包含内部错误详情。

服务端统一判断权限、脱敏失败即中止、密钥仅存服务端、审计不记录原文等安全规则，详见 [AI 安全模型](/zh/security/ai-security-model)。

在自动化任务的运行详情中，可以查看本次运行提出的目录路径、用途、确认状态和按当前时区显示的到期时间，并批准、拒绝或移除已确认目录。目录确认只确定文件范围，不授予读取、写入或发送权限；实际操作仍受任务契约约束。决定提交后会重新读取会话，提交成功不代表任务已经执行成功。移除正在等待的目录会终止这次等待；原目录引用到期也会结束本次等待，不会自动获取新引用或沿用旧批准。已经发生的操作不会被撤回。

任务暂停后可点击“恢复后续运行”，服务端重新检查原授权、契约及当前设备和模型条件，不延长原授权，也不补跑暂停期间。启用的独立任务可“立即运行一次”，这会新建独立运行而不改变日历。运行历史中的“取消本次运行”只针对所选运行；取消意图不代表已派发操作已被撤回。

会话定时任务暂停后也可恢复。恢复要求原会话需求版本未改变、没有未解决的执行结果，且单次时间仍在未来；时间已过请先改期。恢复不会增加会话权限，执行前仍重新检查当前授权。


在任务管理页也可以选择设备和已有会话，创建一次性的会话续跑任务。会话列表只显示当前用户可用的原会话；保存和启用时会再次核对原需求版本。独立自动任务可由用户手动创建，也可从 AI 提出的草稿进入审核，均需要录制和明确授权。

任务列表显示连续失败次数及暂停阈值。没有活动运行时可以修改阈值（默认 3 次）；调高阈值不会自动恢复已暂停的任务。普通失败未达到阈值时，后续周期仍会执行；结果未知或授权失效等暂停原因需要先处理，再明确恢复。

编辑任务要求会使原授权失效，独立任务需重新录制并审核发布。仅修改调度时间不会扩大权限。契约页展示当前授权的版本及批准、到期、撤销时间，并列出与上一版相比的预算、权限、步骤、例外策略及要求变化，可展开查看上一版内容。选择“撤销任务授权”会暂停后续调度，保留历史；已派发的动作仍可能完成。

OSS owner 可以在“设置 → 定时任务预算”配置服务端独立任务上限，初始值为每 UTC 日 24 次、每次运行 64 次工具调用、100,000 个模型 token 和 900 秒。保存按持久化版本核对。降低上限可能阻止现有契约继续执行；提高上限不会扩大任务权限或自动恢复任务。保存冲突或响应不确定时，先重新读取。

改期时会按所选时区回填已有规则。原样保存不会改写 UTC 时间；切换时区会重新显示原规则。修改时间后，先预览未来最多五次执行时间，再确认保存；服务端会复核换算输入与版本，换算结果变化时需重新确认。固定间隔也由服务端换算起点，后续按固定秒数运行。暂停任务的未来时间仅是规则预览，不表示已经启用。

## 后台命令运行期间

同一会话可以同时跟踪多个后台任务，每个任务返回独立的任务 ID，等待、取消和完成回执均按该 ID 关联。新命令是否可执行由被控端的原子并发准入决定：未达到配置上限时继续，达到上限时明确返回容量已满，不排队、不自动重试。同步查询仍可使用。逐命令授权、桌面与浏览器的独占写入限制，以及结果未知时的安全限制继续生效。

后台结果由系统自动回传，无需持续轮询，也无需保持当前 AI 回合开启。普通对话中没有可独立推进的工作时，助手应简短说明任务仍在运行并结束本轮；结束回复不会取消后台任务，也不代表任务已完成。

输入框工具栏提供固定的「后台任务」入口，括号内显示运行中（含取消处理中）的任务数。点击打开侧栏，统一查看当前会话的命令任务和后台工具任务；未结束任务优先，命令历史保留最近 50 条可见记录。命令结果可展开查看，过长内容仅截断展示，原始执行记录保留。点击「取消任务」只针对该任务，最终状态以设备或 Provider 回执为准；设备离线时不能发送命令取消，但仍可查看已有记录。

模型返回可读的思考内容时，已提交的助手消息会显示默认折叠的「思考内容」，点击即可展开；刷新和查看历史仍可恢复。思考与正文分开展示，过长内容仅保留有界展示片段。模型未返回明文思考时不显示该区域，签名、加密内容及内部协议重放字段不会展示。

后续消息没有选择新的上下文、或工具授权次数耗尽，不会移除同一会话中已发生的工具结果与 AI 回复。新的读取和操作仍需授权；达到上下文容量限制时才进行摘要压缩或裁剪。恢复中断会话时，未知的操作结果仍保留为未知。

macOS 的观察区支持 **列出应用**：先返回常规桌面应用的名称与按生命周期生效的选择引用，再点击应用读取其窗口和控件，包括后台应用。不会自动激活应用，也不会在列出应用时采集所有 UI 内容。AI 获得相应读取授权后同样可以选择应用；操作仍需单独确认。切换前台不影响应用选择，但进程重启后须重新选择，本地策略变化仍会限制访问。应用未提供辅助功能内容时可能无法读取，不能据此判断它已经关闭。

普通桌面 UI 动作（点击、选择、聚焦、切换、设置值）的成功仅表示原生 Accessibility/UIA API 调用成功，不表示界面已达到任务预期。被控端不自动比较操作前后的 UI 树或回读属性来判定效果；AI 应在操作后另行读取 UI，判断下一步，并按现有权限申请后续操作。超时、断连等无法确认执行结果的情况仍不得盲目重试。

UI 工具向模型返回对象 ID 和类型，快照元数据与引用有效期只在服务端保留；省略空字段与空动作列表。前端观察面板和设备协议仍使用完整结构。结果被截断时，助手应提高读取深度/节点预算或选择具体窗口继续检查；已批准读取授权耗尽或自然到期后可以重新申请，仍需用户确认，拒绝和撤销不会自动恢复。

UI 读取支持 `scope` 三种范围：默认 `content` 只读取普通界面；`menus` 只读取菜单，适合已有界面信息中找不到目标时补查；`all` 同时读取两者。macOS 的应用菜单栏应使用应用根或默认前台应用，窗口根只读取该窗口内的菜单。范围选择不会替代读取授权或操作确认。

UI 精确读取：`inspect_desktop_ui` 默认深度为 12。可以把已返回的 UI 元素引用作为 `root`，设置 `element_only: true` 只刷新该元素；默认读取其子树。`query` 支持 `native_id`、`role`、`name` 的区分大小写精确匹配，多条件取交集，只返回命中节点。原生 ID 由系统提供，可能缺失；不使用数组下标冒充稳定 ID。搜索仍受深度、访问数量、返回数量、字节和时间预算限制。

截图保留两种方式：`read_current_screen` 不传 `window_id` 时仍截取当前选定显示器的完整画面；通过 `window_id` 传入 `owner_selectable_windows` 中的窗口 ID 时，macOS 使用独立窗口采集，被遮挡不需要切到前台。最小化窗口没有新画面时会明确失败，恢复窗口仍需操作授权。窗口选择不会跳过截图授权。截图转为不含图片的历史文字时，系统校验原始记录，再生成保持原敏感等级、模型授权边界和来源链的新校验记录，避免下一轮因摘要或长度不符中断。

模型历史审计按内容字节预算处理完整记录，不因对话超过 64 条或回复来源超过 256 条而中止；每条记录仍校验摘要和目标模型，来源元数据另有字节上限。容量超限、数据完整性错误与权限拒绝分别报告。加载新工具默认保留当前已加载工具；达到工具数量或描述体积预算时，助手可显式替换工作集，加载本身不授予权限。

批准桌面 UI 操作时，权限批次默认同时包含当前设备的桌面会话与 UI 读取（不含截图），方便操作后检查结果。附带读取默认与操作申请使用相同有效期，每项最多 16 次；它们单独展示并默认勾选，用户可缩短有效期、减少次数或拒绝。已有读取申请的更窄限制保持不变。原生 UI 操作仅支持批准指定应用内的一组动作并限制期限与次数，已移除单次精确输入授权；读取与操作权限可分别撤销，实际调用继续校验当前会话授权、应用归属与本地能力。

新会话的工具工作集最多预加载 4 项，总上限保持 8 项，为按需加载保留空位。数量或描述体积超限时，返回当前已加载工具、数量上限和显式替换方法；失败不改变工作集，也不会自动卸载仍需使用的工具。

## 会话截图与上下文

AI 助手的截图作为会话附件独立保存。刷新页面、重连和上下文压缩不会删除附件；可在会话中查看图片、放大查看完整截图、加载更多图片或删除单张图片。保存的是该次工具调用经审核后提供给模型的截图，不会通过重新截图来替代历史画面。无法恢复此前已经丢弃像素的旧记录。

模型输入中的图片按需使用；转为文字历史时保留工具调用引用，压缩不会触发附件清理。需要再次检查图片时，助手使用 `read_conversation_image` 列出图片引用，再按 `attachment_id` 或无歧义的原 `tool_call_id` 读取。重新读取仍检查当前模型的授权并执行图片安全审核；切换模型不自动授予旧图片的外发权限，历史截图也不会恢复过期的 UI 操作引用或被当作当前屏幕状态。

OSS / Tauri 将图片保存在本机数据目录的 `assistant-images/`，SQLite 只保存附件元数据；Manager 将附件元数据和图片二进制保存在共享 PostgreSQL 表中，多实例使用同一份数据。会话 JSON 不包含图片像素。每张图片沿用模型输入的 400,000 字节上限，每个会话附件总量上限为 100 MiB；超限会明确失败，不会自动删除旧图。

图片默认随会话保留。显式删除图片或会话被删除后，服务端立即停止提供相应图片；后台清理文件或二进制内容。单图删除标记保留到会话删除，防止重放旧结果恢复图片。压缩和权限到期本身都不会删除附件。会话仍受现有历史保留策略约束；“随会话保留”并不绕过该策略。

为降低上下文消耗，助手应在首次读取 UI 后优先按元素引用或 `native_id` / `role` / `name` 精确读取；权限申请仅需选择工具名，Provider 和效果由服务端确定。失效授权按工具和状态汇总，当前有效的精确操作参数仍保留供核对。工具结果不会因授权到期提前从历史中裁剪。


AI 申请会话定时任务时只保存待确认申请，不保存任务草稿；本轮会等待用户决定，同时在对话中直接展示审批卡片，与权限申请保持相同风格，展示任务内容和执行时间。等待期间不会继续调用模型；用户通过或拒绝后，服务端将明确结果交回同一轮 AI，再继续回复。点击发送按钮处的「停止」可结束等待，申请不会因此自动通过。点击「通过并启用」才创建正式任务，点击「拒绝」会拒绝申请并保存回执；无需再发送聊天确认。卡片没有关闭操作，只有明确点击通过或拒绝才提交决定；多个申请可同时显示。服务端确认后展示结果，失败时保留提示供核对和重试。待确认和已拒绝申请不出现在任务管理列表中。已启用的会话定时任务会保留，后续普通聊天（包括“确认了”）不会取消任务；只有显式暂停或取消才停止调度。到期后等待会话空闲，在原会话最新上下文中执行用户已批准的任务内容。执行开始时固定输入版本，执行期间的新输入仍会阻止旧轮次继续操作。授权会重新校验，不延长有效期或扩大权限。

“5 分钟后”等相对时间从点击启用并由服务端确认成功时开始计时。审核前保存并展示待确认的延迟，不计算绝对执行时间；启用时转换并保存为绝对 UTC 时间；界面按所选时区显示。启用回执保存在原会话中，不新增用户输入，也不授予任何工具权限。独立自动任务仍需完成录制、权限审核和发布。

AI 可通过 `list_conversation_scheduled_tasks` 查询当前会话的定时任务，返回服务端实际状态、创建来源、执行时间和是否可取消。通过 `cancel_conversation_scheduled_task` 可直接取消由 AI 创建的任务，无需额外权限或审核；用户手工创建的任务只能查询，必须由用户在任务管理页面取消，不能通过权限申请绕过。是否由 AI 创建以服务端记录的最初创建来源为准，用户确认启用不会将 AI 提案变为手工任务。取消停止后续调度；已经开始执行时返回“已请求取消”，不承诺撤销已发生的外部操作。

服务重启或执行进程中断后，已过期的执行租约不会让会话持续显示为运行中。页面恢复服务端状态后会解除停止等待，保留历史并允许创建新会话；后台命令仍有独立生命周期，不会随会话状态恢复被取消。

会话执行期间可以新建或切换历史会话，原会话继续在后台运行。会话列表以旋转圆环标识运行中的会话，运行中的排在最前，其余按最后活跃时间从新到旧排序。点击删除会先弹出确认框；运行中的会话另有提示。确认删除后移除历史和图片、停止该会话继续处理并取消关联的会话定时任务。后台命令采用尽力停止策略，不保证一定停止，也不会撤销已执行的操作。

输入区固定在助手页面或远程桌面助手面板的底部，消息区独立滚动并默认跟随最新内容。向上滚动查看历史时暂停跟随，点击右下角“回到最新消息”按钮或手动滚到底部即可恢复跟随。切换会话后默认定位到最新消息。

会话目录右侧的“定时任务”打开当前会话的定时任务列表，包含已完成任务。对话主区域只保留待审批任务卡片。上下文用量圆环支持点击查看详情；输入区按钮以及顶部的会话列表、设置会话定时续跑、新会话按钮，均在空间不足时收起文字，保留图标。

macOS 语义 UI 操作在审批后重新查找并验证原目标的进程和元素身份；人工输入会抢占执行，但不会仅因点击审批就清除语义目标引用。坐标快照、引用到期和工作进程重启仍会使对应引用失效。操作失败时，助手收到原始错误并自行读取当前应用状态，再决定下一步。结果不明确只作为警告，不阻止后续已授权写入，也不需要用户确认或关闭记录；原始回执保留，不能仅凭失败就重复执行。

操作结果待核对卡片默认显示操作类别、回执不确定的说明及核对步骤；请求与执行标识收在默认折叠的排查详情内。记录没有具体错误原因时会明确说明，不将内部标识当作错误解释。

执行失败或结果待核对时，会展示实际消耗授权所对应的原权限申请理由，帮助识别该操作的目的。关联依据是服务端执行记录和授权使用记录；没有对应记录时不会根据相近时间或相似参数猜测。申请理由只用于解释操作目的，不代表错误原因，也不会赋予新的权限。

### 稳定的 UI 元素标识

UI 结果中的 `element_id` 与该元素的 `object_ref.token` 相同，标识被控工作进程内的一个原生元素。重复读取、不同搜索范围、文本或数值变化，以及授权过期/重新授权不会重新分配该 ID。macOS 使用保留的 AXUIElement 原生对象比对，Windows 使用进程生命周期内的 RuntimeId 与保留的 UIA 元素；不按树中序号、名称或位置认定为同一元素。原生元素销毁重建、应用重启或工作进程/桌面会话重建后，旧 ID 不再代表新元素。

桌面对象引用按原生对象生命周期生效，不设固定过期时间。重复读取未变化的应用或控件会复用 ID 和存储映射；对象销毁重建、应用重启、worker 或桌面会话更换后引用失效。执行前仍校验原生对象、应用归属和有效授权，授权按用户批准的时长和次数生效，不再被引用期限缩短。引用存储有容量上限，需要时回收失效的 UI 映射；仍满时拒绝新增引用，保留已有存活 ID。

### 会话授权与原生值类型

授权按当前会话和批准范围生效，普通消息（例如“继续”）不会使授权失效，也不会清空已经加载的工具详情。有效期、次数、撤销和具体操作的参数约束仍然生效。缺少权限时，助手直接提交审批卡片；输入已知的多个操作可以合并申请，不必先在聊天中再次征求同意。

macOS UI 的 `set_value` 按控件原生值类型执行：文本使用字符串，数值要求有限十进制数，日期接受带时区偏移的 RFC3339、`YYYY-MM-DD`（保留本地时间）或 `HH:MM[:SS]`（保留本地日期）。读取日期时返回带时区偏移的时间；非法格式或不支持的值类型在写入前返回明确错误。

### 应用范围授权与控件搜索

处理应用内的多步操作时，AI 可以申请当前会话的应用范围授权。审批卡片显示从设备观察结果取得的应用名称，以及允许的点击、选择、聚焦、切换或填写动作；用户可以缩小动作范围、有效期和次数。每次执行仍校验会话、有效授权、真实控件所属应用及进程身份。其他应用、原始键鼠输入与截图不在该操作授权内；桌面读取作为单独的审批项展示。原应用重启后需要重新观察和申请；引用年龄不影响已批准的授权期限。原生 UI 操作只使用应用范围授权。

普通聊天、审批后的继续与会话定时续跑均按数据库中的有效授权恢复工具范围，不因新增消息而丢失权限。申请批次校验失败时整批不创建审批卡片，AI 会收到错误项、所需参数结构和前置读取指引。

UI 搜索必须提供条件。`query.any` 支持多个名称、原生 ID、角色或控件类型的模糊搜索，任一命中即返回，并标明命中项；日期/date、时间/time、输入框/input、按钮/button、弹层/popover、对话框/dialog 等使用明确的中英文别名。`role`、`native_id`、`element_id` 等精确条件仍同时生效。可先定位弹层，再在其内部查找控件；未命中不代表系统不支持操作。只有明确传入 `allow_unfiltered=true` 才会进行有界全量读取。

原生 UI 权限申请只使用 `application_scope`，不接受 `exact_input`；每次执行必须携带已批准的 `application` 引用、当前控件 `target` 与 `action`。加载工具详情不创建审批申请；只有 `request_capability_grants` 返回带 `request_id` 和 `pending_user_decision` 的成功回执后，助手才可告知用户审批卡已提交。


桌面 UI 工具面向模型只使用 ID：读取使用可省略的 `root_id`，语义操作使用 `application_id`、`element_id` 和 `action`，应用授权申请使用 `application_scope.application_id`，窗口截图使用 `window_id`（省略时仍截取当前显示器）。模型不再提供快照 ID 或引用有效期；服务端从当前会话的读取记录解析完整引用，并继续校验对象存活、对象类型、应用归属和操作授权。局部回读不会覆盖其他控件的引用。引用失效会明确要求重新读取，未知 ID 不会触发全量搜索，也不会自动申请新权限。历史读取结果仍保留；对象生命周期和授权有效期分别校验。Windows 兜底输入也使用 `application_id`，保留既有精确输入审批。

工具调用按对话顺序展示为默认折叠的记录，展开后可查看工具名称、入参和出参（包括错误信息）。实时调用在结果返回后更新；重新打开会话或加载之前消息时也能查看已保存的记录。未收到结果会明确提示，界面只能展示服务端保留的数据。

设备能力状态有效期为 60 秒，每 25 秒刷新上报。诊断日志记录采集延迟或缓慢、上报通道关闭、状态无效或过期，以及执行前缺少有效状态，不记录 UI 内容或工具载荷。

AI 界面搜索会组合中文标签与英文名称、原生标识及控件类型（每批最多 16 项），即使界面是中文也应尝试 date/time/input 等英文候选。搜索未命中不代表功能不支持；已授权且支持点击的日期等入口，应由助手自行展开并继续读取。助手须核对实际编辑的控件和结果，不能把快速输入框或既有日程误当成已完成的编辑。桌面引用按原生对象生命周期校验，授权时长与次数单独校验。每轮模型请求提供当前 UTC 时间；设备本地日期与时区仍须依据当前设备/应用证据或用户明确说明，不能从语言或服务端时区推测。

### macOS 后台鼠标和键盘（实验性）

优先使用语义 UI 控件操作；当语义 UI 无法表达所需操作，或根据观察及实际结果确认难以可靠完成时，再结合目标应用窗口的当前截图使用后台输入。截图通过 `read_current_screen` 指定 `window_id` 获取，必要时刷新。存在适用的语义 UI 操作时，不应默认改用后台输入。

AI 可通过 `execute_background_inputs` 向已观察到的应用窗口发送单击、双击、滚动、Unicode 文本和带修饰键的按键。工具使用应用 ID、窗口 ID，以及控件 ID 或窗口截图中的归一化坐标（0–1000）；PID、窗口几何和引用元数据由服务端处理。鼠标目前仅支持主按钮，拖拽暂不支持。

权限卡按当前会话中的应用和动作范围批准，可缩小有效期、次数及动作；批准后范围内的操作复用授权，默认包含桌面与 UI 读取，截图单独授权。后台输入与语义 UI 操作是独立工具，不能互用权限。设备本地的应用访问策略仍生效。

输入定向发送，不主动激活应用、移动真实光标或回退到前台输入。键盘要求目标窗口是该应用当前接收键盘输入的窗口；最小化或无法唯一定位的窗口会返回错误。坐标操作需要窗口截图，窗口尺寸变化后应重新截图；控件定位使用执行时的控件位置。其他前台应用的用户输入不会自动抢占这项后台操作，用户停止会话仍会取消后续事件；已发送的事件无法撤回。

结果仅说明事件投递，AI 需重新读取 UI 或截图确认实际结果。失败会返回具体原因，部分投递会说明已发送的事件数，不要求用户确认“未决”结果，也不阻止后续已授权操作。鼠标路径依赖运行时探测的非公开 macOS API；不可用时鼠标返回不支持，键盘能力不因此禁用。已验证环境为 macOS 15.6.1 的 TextEdit；Command+A 在该背景条件下未生效，不能假定其他应用和系统版本具有相同表现。

### 批量 UI 与后台输入（试用）

AI 当前只看到 `execute_ui_actions`（语义 UI）和 `execute_background_inputs`（后台键鼠）两个批量入口；原单动作入口暂时隐藏。每批 1–20 步，一个步骤也必须放在 `steps` 数组中。每批限定同一个应用，后台批次还限定同一个窗口；两类操作暂不混在同一批。

批准范围必须覆盖批次全部动作；复用会话应用授权，一次批量调用消耗一次授权使用次数。整批封存并持有同一个执行租约，步骤依次执行，出错即停，不回滚、不自动重试。批次总执行期限仍受既有 30 秒派发期限及授权/取消限制约束。

默认不增加步骤间固定等待，只保留原生键鼠事件所需间隔。遇到打开窗口、布局变化等异步依赖，应结束当前批次，读取 UI 或应用截图后再提交。优先语义 UI，确实不好操作时才结合窗口截图使用后台输入。

成功只返回完成步数；执行中失败只返回失败步骤编号、具体错误和该步是否可能产生效果，编号前的步骤已完成原生调用，后的步骤未执行。整批预检失败则明确所有步骤均未执行。原始入参保留在默认折叠的工具记录中。原生调用完成不代表业务结果符合预期，AI 仍需回读；失败记录无需用户确认，也不阻断新的授权内操作。
