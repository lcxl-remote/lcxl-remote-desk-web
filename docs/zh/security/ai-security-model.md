# AI 安全模型

能读取系统状态的 AI + 远程桌面非常强大——也因此需要强健的信任边界。LCXL Remote Desk 把 AI 当作一等控制端，并由一组**安全相关、破坏即回归**的不变量来约束。

## 服务端是唯一可信源

所有授权逻辑均在**服务端**校验。`request_id`、`target`、`actor`、`scope`、`caller`、最终的 `risk`、`approval_id` 等字段由服务端注入与校验——控制端（浏览器、移动端或 MCP）**永远无法自报**。浏览器侧请求体在结构上甚至不包含这些字段。

## 能力协议面向设备

能力协议描述**对设备能做什么**，与调用者无关。读权限点由输入**派生**（`OperationInput::capability()`），从而杜绝能力、证据采集与审计三者之间的漂移。

## 默认只给建议

默认执行模式为**只给建议**：模型只能提出命令、不能执行。更高风险动作需经**服务端中介的显式确认**。

## 脱敏 fail-closed

诊断编排器按 **采集 → 脱敏 → 模型 → 渲染** 运行。若脱敏失败，请求会在调用模型**之前**中止。证据在到达模型前一定已脱敏。

## API Key 是服务端密钥

AI 模型 API Key **绝不**回传浏览器、**绝不**进任何公开 `/settings` DTO、**绝不**写日志。

## 审计只记元数据

审计轨迹只记录无内容的摘要——计数、大小、token 用量、provider、adapter。原始 prompt、输出与截图**绝不**留存。

## MCP 只读

MCP 工具集是**静态白名单**，从构造上就没有执行 / 写入 / 控制类工具（“未定义即不可达”）。`lcxl_diagnose` 的 provider 签名不带截图选项，因此 MCP 客户端在结构上无法抓屏。见 [MCP 服务](/zh/features/mcp-server)页。

## 模型无关

wire 协议被隔离在 adapter 之后（`openai.rs` 对应 OpenAI 兼容、`anthropic.rs` 对应 Anthropic Messages）。新增供应商即新增一个 adapter——编排器不变。
